# Research Link Manager for Zotero 9

Research Link Manager creates a filesystem view of stored Zotero PDFs under a
configurable Windows directory. Collection folders are mirrored and each PDF is
a hard link or symbolic link to Zotero's managed file. PDFs are never copied.

The official Edge Zotero Connector is not modified. See [ARCHITECTURE.md](ARCHITECTURE.md)
for the source-level analysis and API boundary.

## Behavior

- Default Research Root: `C:\Research`
- Default link mode: `Auto`
- `Auto` uses a hard link when both paths have the same drive letter and a
  symbolic link otherwise.
- Only stored PDF attachments in the user library are mirrored.
- A child PDF attachment inherits its parent item's direct Collection
  memberships.
- Top-level Collections become direct children of Research Root.
- An attachment in multiple Collections receives one link in each directory.
- PDF links are named from Zotero metadata as `Title - Year [attachmentKey].pdf`. Missing
  years are omitted, and missing titles fall back to
  `attachment-<attachmentKey>`.
- Every filename includes its stable attachment key. Adding or deleting another
  item with the same title never renames an existing Research link.
- Existing ordinary files are never overwritten.

## Build

Requirements:

- Windows PowerShell 5.1 or newer
- Node.js 20 or newer for tests

Run:

```powershell
npm test
npm run build
```

The installable file is written to:

```text
outputs\research-link-manager-0.1.7.xpi
```

## Install

1. In Zotero, open `Tools -> Plugins`.
2. Open the gear menu and choose `Install Plugin From File...`.
3. Select `research-link-manager-0.1.7.xpi`.
4. Open `Edit -> Settings -> Research Link Manager`.
5. Confirm the Research Root and link mode, then choose `Apply and Sync`.

The packaged manifest is deliberately restricted to Zotero `9.0.*`, the
version family verified during development.

Zotero 9 requires every desktop plugin manifest to declare an HTTPS
`applications.zotero.update_url`. This local build uses the reserved
`example.invalid` domain, so it never downloads updates. Replace that URL with
a real hosted Zotero update manifest before publishing the plugin. The
manifest also declares `data_collection_permissions.required: ["none"]`:
Research Link Manager does not send Zotero or Research data anywhere.

## Configure and repair

The settings pane exposes:

- Research Root
- `Auto`, `Hard link`, or `Symbolic link`
- startup synchronization toggle

Use `Tools -> Sync / Repair Research Links` at any time to reconstruct missing
links, update renamed PDFs, reconcile Collection moves/membership changes, and
remove obsolete plugin-managed links.

Sync is idempotent: repeated or overlapping requests are serialized. Repair can
also recover links created by an interrupted sync when their NTFS identity
matches the Zotero source exactly, and removes only a matching
`[attachmentKey]` duplicate that has the same file identity.

Changing Research Root requires confirmation. Cleanup of the old root is
limited to links that still match the recorded link identity and directories
that the plugin created and that are empty. The root itself is never removed.

## Logging and state

Operational messages are written to Zotero's debug/error log with the prefix
`[Research Link Manager]`. Messages include attachment key, Collection key,
source, destination, link type, and error text where relevant.

Ownership state is stored in the Zotero profile as:

```text
research-link-manager-state.json
```

Do not edit this file while Zotero is running. It is not stored under Research
Root, so existing Research content is not treated as plugin-owned.

## Safety guarantees

- No direct SQLite access.
- No changes to Zotero metadata or stored files.
- No PDF copies or fallback copies.
- No overwrite of unmanaged files.
- No recursive deletion of Research Root.
- Link deletion requires an ownership record and root containment. Unmanaged
  paths still require identity verification and are never adopted or deleted
  by filename alone.
- A notifier or link error is caught and logged after Zotero's save transaction;
  it cannot turn a successful Connector capture into a failed Zotero save.

## Known limitations

- Group libraries are not mirrored in v1.
- Linked-file attachments are excluded; only Zotero-managed stored PDFs are
  included.
- A Collection's items appear only in that exact Collection directory, not in
  all ancestor directories.
- Symbolic-link creation depends on Windows Developer Mode or elevated
  privileges. Failure is logged and never falls back to a copy.
- Runtime changes trigger a debounced full user-library reconciliation. This is
  robust but can be slower for very large libraries.
- If a managed path has been replaced with an ordinary file, the plugin refuses
  to delete it. Manual review is then required.
